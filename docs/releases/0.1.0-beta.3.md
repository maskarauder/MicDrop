# MicDrop 0.1.0-beta.3 — Windows, Linux, macOS, Android, and optional iPhone beta

This candidate expands volunteer beta testing to Linux x64 and macOS 14.2+
(Apple Silicon arm64) desktop and CLI hosts alongside Windows 11 x64,
Android 12+ arm64, and optional sideloaded iPhone (iOS 17+ arm64). Build,
package, and smoke-test this candidate before sharing; these notes do not
record new physical hardware acceptance beyond automated CI contracts.

## Included in this candidate

- **Linux x64 desktop and CLI host (`MicDrop-<version>-linux-x64-host.tar.gz`)**:
  GTK3 slate/gold desktop interface (`./micdrop-host desktop`) with optional
  AppIndicator3/Ayatana tray integration, XDG `.desktop` launcher/autostart
  helpers (`--install-launcher` / `--uninstall-launcher`), runtime GTK/PulseAudio
  loading so headless CLI commands run without display libraries installed, and
  PulseAudio / PipeWire-Pulse monitor capture and virtual-cable return.
- **macOS 14.2+ Apple Silicon desktop app (`MicDrop-<version>-macos-arm64-app.zip`)
  and CLI host (`MicDrop-<version>-macos-arm64-host.tar.gz`)**: Native AppKit
  slate/gold desktop window and menu-bar status item (`MicDrop.app`), ad-hoc
  code signing, Core Audio Process Tap (`CATapDescription`) output capture,
  HAL virtual-cable return, Bonjour LAN discovery, and Keychain-backed host
  secret protection.
- **Windows 11 x64 desktop host**: Per-user installer, portable ZIP, tray
  controls, opt-in phone settings exchange, configurable connection-log
  retention, and pointer-lifetime hardening across Win32 GUI and native WebRTC
  ICE configuration bridges.
- **Android 12+ arm64 (`MicDrop-<version>-android-arm64-dev.apk`) and optional
  iPhone iOS 17+ arm64 (`MicDrop-<version>-ios-arm64-unsigned.ipa`)**: Matching
  slate/gold mobile interfaces, **Diagnostics** with stream reports (plus
  Android crash reports), local output check, paired LAN playback, microphone
  return, duplex with bounded network/route recovery, and open-source notices.
- MPL-2.0 license and third-party dependency notices in every packaged archive
  and application bundle.

Android version code is **4** (and macOS/iPhone `CFBundleVersion` is **4**).
Both mobile apps retain the provisional `com.maskarauder.micdrop.dev`
identifier so matching-signer updates preserve saved pairings and preferences;
`MicDrop.app` on macOS uses `com.maskarauder.micdrop.mac`. Preserve the Android
development signing key for subsequent beta updates.

## Before testing

Install or extract the matching desktop host package for your computer
(Windows setup or portable ZIP, Linux x64 `.tar.gz`, or macOS arm64
`MicDrop.app` ZIP / CLI `.tar.gz`) together with the matching Android APK or
unsigned iPhone IPA from this candidate. Follow the `BETA_TESTING.md` guide and
repository `README.md` for platform-specific setup.

Start with local-network playback on the phone speaker, then try your
headphones. Phone microphone return requires a virtual audio cable (such as
VB-CABLE on Windows, BlackHole on macOS, or a PipeWire/PulseAudio null sink +
remap source on Linux) and explicit microphone permission on the phone.

## Known limits

- Windows and Linux packages are unsigned; macOS `MicDrop.app` and `micdrop-host`
  are ad-hoc signed without Apple Developer ID notarization, so Gatekeeper or
  SmartScreen warnings may appear.
- Android is a sideloaded, debuggable development build, not a Play Store release.
- The iPhone package is an unsigned development IPA; free Apple ID signatures
  expire after 7 days and broader physical route/background/remote checks
  remain open.
- Physical macOS audio hardware validation remains open pending real-device
  testing.
- Bluetooth buffering can add delay. A classic Bluetooth headset microphone can
  switch audio to voice quality; LE Audio and hearing-aid coverage is limited.
- One active phone stream per desktop host is supported.
- Settings marked for the next connection require Stop/Connect in this build.
- Remote testing requires separate host/relay setup; it is not required for LAN.

Network RTT and buffer statistics do not measure physical audio delay.
Record unsupported hardware tests as skipped, with the reason.

First-party source is MPL-2.0. Recipients must receive access to the matching
source tag/commit (or an exact source snapshot) and applicable notices alongside
any distributed binaries.
